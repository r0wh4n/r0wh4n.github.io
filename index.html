Notes

Problems I’ve dug into and solved, written down so the lesson sticks.

  1. Jul 2026The bug that only ate Windows uploadsDebugging · data pipeline2 min read

    The symptom

    On an internal platform I built, usage data from Mac laptops showed up on the dashboard. Data from Windows laptops never did, even though the upload logs said every file had arrived.

    Root cause

    The difference was three invisible bytes at the start of every Windows file. Windows PowerShell 5.1 writes a UTF-8 byte-order mark when you ask for UTF-8. The import job’s JSON parser choked on it, counted the file as an error and quietly moved on, so nothing ever failed loudly.

    The fix

    Strip the byte-order mark before parsing, on both the laptop side and the import side. Because the importer change also applies to files that were already uploaded, the missing Windows history came back without anyone re-sending anything.

    What I took away

    A silent skip is worse than a crash. When a pipeline drops data, it should say so loudly.

  2. 2026Why Ping rooms are scoped to a folderSecurity design · Ping2 min read

    The problem

    Ping lets your coding agent join rooms with other people’s agents. Every room you had ever joined was delivered into whatever project you happened to be working in, together with that room’s write token, because the agent needs it to reply.

    Why it matters

    If you’re in rooms for two different teams or clients, one agent holding both is one wrong argument away from posting one client’s context into the other’s room. Context shared into the wrong room can’t be taken back.

    The fix

    A room now only delivers messages while you’re working inside the directory you joined it from, and /ping here or /ping anywhere moves it either way. The tool that shares context into a room must name the room, and it’s refused if the name doesn’t match the token being used.

    What I took away

    With AI agents, the dangerous bug isn’t a crash. It’s the agent doing exactly what it was told, in the wrong place.

  3. Sep 2026Taking this site from 19 to 60 fpsPerformance · this site2 min read

    The symptom

    The intro felt slow and choppy. On my Mac it looked fine, but with the CPU throttled to a typical laptop’s speed, the dot sweep dropped to about 19 frames a second, and nothing appeared until all the JavaScript had loaded.

    Root cause

    Two things. The wallpaper redrew about 26,000 halftone dots on every frame of the sweep, and the whole entrance waited for JavaScript to download and start before anything moved.

    The fix

    Draw the dots once, then reveal them with a CSS clip-path the GPU animates almost for free. Move the entrance to plain CSS keyframes, so it starts on the very first paint.

    Result

    60 fps with zero dropped frames on the same throttled CPU, and an entrance that settles in about 1.5 seconds. The lesson: measure on a slow machine, because my own laptop was hiding the problem.
